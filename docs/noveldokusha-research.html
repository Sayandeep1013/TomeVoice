NovelDokusha: how it works, and bringing it to TomeVoice

Research note · 23 Oct 2026 · read from the source at github.com/nanihadesuka/NovelDokusha and the copy on the phone

TomeVoice can get NovelDokusha's "search, add the novel, get new chapters every day" flow. NovelDokusha's search is not a service. Each site is one Kotlin class that knows its search URL and CSS selectors, and "search everywhere" just asks all of them at once. The plan below builds the same thing in TomeVoice, with sites described as data so a broken one can be fixed without a new APK. Nothing here is built yet.

1. What NovelDokusha is

NovelDokusha is an open-source Android reader for web novels and local EPUBs. It is GPL-3.0, the same licence as TomeVoice, so its ideas and code can be reused here. The project is marked as no longer maintained.

PartWhat it uses
UIKotlin, Jetpack Compose
NetworkOkHttp, plus a hidden WebView for Cloudflare
Reading site pagesJsoup (CSS selectors over HTML)
Text from any pageReadability4J (finds an article's main text)
StorageRoom (SQLite), database bookEntry, schema version 5
Background workWorkManager
SpeechAndroid TextToSpeech plus a media-controls service
TranslationGoogle ML Kit, on the device

On this phone: my.noveldokusha v2.2.0. It has 2 web novels, with 407 and 678 unread chapters, and 3 local A Song of Ice and Fire EPUBs.

2. The flow, start to finish

Everything goes directly to the sites. There is no NovelDokusha server in between.

  1. Find a novel. Browse one source's catalogue (popular, latest), search one source, or use global search, which asks every source at once. A separate "database" search looks on NovelUpdates and BakaUpdates for information about a novel, not its text.
  2. Open the book page. The source supplies the cover URL, the description and the full chapter list (a title and URL for each chapter).
  3. Add to library. This saves the book and its chapter rows. No chapter text is downloaded yet.
  4. Read a chapter. The chapter page is fetched and the source pulls out the body text. The text is saved, so the chapter opens offline next time. You can also download chapters ahead.
  5. Keep your place. It saves the last chapter read and the position inside it, and marks chapters read as you go.
  6. New chapters. A background job re-fetches every library book's chapter list on a schedule, adds the new ones and notifies you (section 6).
  7. Any other site. Open a URL with no matching source and Readability4J guesses the page's main text.

3. How providers work

A provider (a "source") is one Kotlin class per website. It hard-codes that site's URLs and the CSS selectors for titles, covers, chapter links and chapter text. All of them are registered in one list, scraper/Scraper.kt. A URL is matched to its source by checking which source's baseUrl it starts with.

The interface has two levels:

LevelWhat it must doCount
SourceInterface.BasegetChapterText(doc): pull the readable text out of a chapter page. Only reads chapters you link to.3 sites
SourceInterface.CatalogEverything in Base, plus getCatalogList(page), getCatalogSearch(page, query), getChapterList(book), cover URL, description, language, catalogUrl and baseUrl.23 sites

A Catalog source, simplified:

class NovelBin(private val networkClient: NetworkClient) : SourceInterface.Catalog {
    override val id = "novelbin"
    override val baseUrl = "https://novelbin.me/"
    override val catalogUrl = "https://novelbin.me/sort/novelbin-daily-update"
    override val language = LanguageCode.ENGLISH

    // search:   GET  the site's search page        -> select result rows -> (title, url, cover)
    // chapters: GET  the book page                -> select chapter links -> (title, url)
    // text:     GET  the chapter page             -> select the text container -> paragraphs
}

The weak point: when a site changes its HTML, its selectors stop matching and that source returns nothing until someone edits the code and ships a new APK. Sites of this kind also move domains, which breaks the baseUrl match.

4. How global search works

When you type a name, the search screen makes one result row per Catalog source and starts all of them at the same moment. Each calls getCatalogSearch(page 1, query) on its own site and fills its own row as soon as it answers. Scrolling a row fetches that site's next page. A slow or broken site only affects its own row. That is why one search shows the same novel from several sites.

6. New chapters every day

New chapters come from LibraryUpdatesWorker, a periodic WorkManager job. The interval is set in hours (24 hours by default), and the job runs only on a network connection with the battery not low. A manual "update now" runs the same job once.

7. Data model and backups

Three tables hold everything a web novel needs. The URL is the key throughout, which is why a site's domain change breaks the link to existing books.

TableKeyOther columns
Bookurltitle, completed, lastReadChapter, inLibrary, coverImageUrl, description, lastReadEpochTimeMilli
Chapterurltitle, bookUrl, position, read, lastReadPosition, lastReadOffset
ChapterBodyurlbody: plain text, paragraphs separated by blank lines, pictures as <img src … yrel …> markers

Backup file. Settings → Backup writes a ZIP containing database.sqlite3 and, optionally, the books/ folder of local files and images. The app's own database is private, so this backup is the only way TomeVoice can read the novels already on the phone. Importing it is simple: open the SQLite file, read the three tables and turn each book into a TomeVoice book.

8. Reading, speech and translation

  • Reader: a scrolling list of paragraphs that loads the next chapter as you reach the end.
  • Speech: TextToSpeechManager reads the chapter through Android's TTS. NarratorMediaControlsService adds a notification and lock-screen controls. TomeVoice already does more here: its own audio pipeline, word highlighting, sleep timer and screen-off playback.
  • Translation: ML Kit translates the chapter on the device, paragraph by paragraph, for machine-translated reading of untranslated novels.
  • Cloudflare: when a site answers with a challenge, an interceptor loads the page in a hidden WebView to earn the cf_clearance cookie and retries. If that fails, a visible WebView lets you solve it by hand.

10. Plan for TomeVoice

A web novel fits TomeVoice's existing model: a Book whose sections are chapters, with chapters fetched when needed and appended over time. The reading position is already kept across re-parses, so new chapters can be added without losing your place. Chapter HTML goes through the same HTML-to-blocks code the EPUB reader uses.

PHASE 1

Import a NovelDokusha backup

Pick the backup ZIP, read its SQLite database, and bring every novel across with its saved chapters, read marks and position.

Moves the 2 novels on the phone over. Works offline.

PHASE 2

Add a novel by URL

Paste a book or chapter link. A generic extractor (the Readability approach in Dart) finds the chapter text and the "next chapter" link.

Works on most sites with no per-site code.

PHASE 3

Daily new chapters

A WorkManager job in the Kotlin layer re-checks each web novel once a day, diffs chapter URLs, downloads the new chapters' text and notifies.

Unlike NovelDokusha, new chapters are ready offline.

PHASE 4

Sources and global search

Each site is a small JSON file: search URL, and selectors for results, chapter list and text. Global search runs every enabled source in parallel, one row each.

Fix a broken site by editing JSON, not by releasing.

A source as data might look like this:

{
  "id": "novelbin",
  "name": "NovelBin",
  "baseUrl": "https://novelbin.me",
  "language": "en",
  "search":   { "url": "/search?keyword={query}", "item": ".list-novel .row",
                "title": "h3 a", "link": "h3 a@href", "cover": "img@src" },
  "chapters": { "url": "{book}#tab-chapters", "item": "ul.list-chapter li a",
                "title": "@title", "link": "@href" },
  "text":     { "body": "#chr-content", "remove": ["script", ".ads"] }
}

The selectors above show the shape only. Each would be checked against the live site when the source is written.
